# Keep the broken provider selectable; surface the failure instead of hiding the model

When the GCloud OAuth refresh token goes invalid (`invalid_grant`), we could also `pi.unregisterProvider(litellm)` — the API exists and takes effect immediately — so the broken models would vanish from the catalog until reauth. We chose not to: the provider stays selectable, and the failure is surfaced instead (one error toast + a persistent footer warning + a short non-retryable chat line, per `docs/roadmap/litellm-auth-error-surface.md`). A model quietly disappearing from `/model` is more confusing than a selected model that visibly explains why it can't authenticate; keeping it visible also keeps the reauth path one step away (user sees the error, runs the command, retries the same prompt). The cost accepted: each prompt while broken still burns one (short, non-amplified) chat line.
