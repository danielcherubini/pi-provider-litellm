# Use createProvider for model catalog lifecycle

The config-form `pi.registerProvider(id, config)` works but requires us to hand-roll cache-first-then-live startup, a 45-minute token refresh timer, and a `reregister()` helper for gcloud auth. We switched to `createProvider({ fetchModels })` from `@earendil-works/pi-ai` so pi owns the disk cache (`models-store.json`), restoration, and refresh lifecycle, eliminating `model-cache.ts` and the refresh timer entirely. The trade-off is importing a deeper API surface (`createProvider`, `openAICompletionsApi`, `ProviderAuth`) and expressing ambient gcloud auth as an `auth.apiKey.resolve()` callback rather than a static `apiKey` field. We accepted this because the result is less bespoke infrastructure and the pi-managed cache benefits from pi's own locking and generation-guard fixes.
